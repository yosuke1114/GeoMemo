## 1. サマリー

GeoMemo は「地図が主役・モノクロ基調・大文字ラベル」という独自の見た目で統一されており、空状態・エラー文言・VoiceOver ラベルも共有まわり（依頼する／見守り／フレンド管理）では丁寧に作られています。一方で、次の 4 点が体験と審査の両面で大きなリスクです。

画面で確認できたのは 10 画面だけで、ダークモード・最大の文字サイズ・英語・iPad は撮れていません（§0）。以下はコードの確認が中心です。

1. **位置情報「常に許可」の説明が足りない。** オンボーディングは「使用中のみ」の説明だけで、直後に「常に許可」のダイアログが自動で続きます。許可が足りないとき（拒否／使用中のみ／通知オフ／監視 20 件超過）にアプリ内で何も知らせません。位置情報の用途文（Info.plist）は英語のみで、依頼者への到着通知に触れていません。
2. **依頼を「受け取る側」の体験が途切れている。** 自分のメモが 0 件だとリストに受信した依頼が出ません。「完了」はリスト行にしかなく、詳細画面からは完了できません。「到着すると依頼者に通知される」ことが受信画面に書かれていません。
3. **「誰に何が見えるか」が送信画面で分からない。** 非公開招待に変えた意図（選んだ相手だけが開ける、相手に見える項目、依頼者に戻ってくる情報）が UI に出ていません。宛先の分からないアプリ（LINE 等）では届かないという制限も画面にありません。
4. **日英が混在している。** 共有機能の文言は日本語のみ（英語設定でも日本語が出る）、逆に「お気に入りの場所」やペイウォールの一部、許可ダイアログは英語のみです。

そのほか、地図ピンのタップ領域と VoiceOver、コントラスト、Dynamic Type の固定サイズ、Reduce Motion 未対応、破壊的操作の確認不足、独自ナビゲーションバーと iOS 26 以降の標準との乖離を挙げています。

## 2. 指摘事項（優先度順）

### 高

#### H-1 「常に許可」の理由を説明する画面がなく、ダイアログが連続する

- 画面: オンボーディング 2 ページ目（位置情報）→ システムの許可ダイアログ
- スクリーンショット: `01-onboarding-welcome-ja.png`、`02-onboarding-location-ja.png`、`03-onboarding-location-dialog-ja.png`
- 確認: 画面（説明文、英語の用途文）＋コード（ダイアログの順序。「常に許可」のダイアログ自体は撮れていません。`OnboardingView.swift` `handlePrimaryAction`、`LocationManager.swift` `locationManagerDidChangeAuthorization`、`SplashView.swift`）
- 問題:
  - 説明文は「エリアに近づいたときにメモをお知らせするために使用します」だけで、**アプリを閉じていても通知するために「常に許可」が必要**であることを書いていません。
  - 「続ける」を押すと `requestWhenInUseAuthorization()` を呼び、**結果を待たずに 3 ページ目（通知）へ進みます**。「使用中のみ」を許可した瞬間にデリゲートが `requestAlwaysAuthorization()` を呼ぶため、通知の説明ページの上に「常に許可」のダイアログが重なります。ユーザーは何の説明も読まないまま 2 つ目の位置情報ダイアログを見ます。
  - 起動のたびに `SplashView` が（位置と通知が許可済みなら）`requestAuthorization()` を呼び、「使用中のみ」のユーザーに「常に許可」を要求し直します（iOS は 1 回しか出しませんが、意図が読み取れません）。
  - ボタンは「続ける」だけで、「あとで」がありません。
  - ページは横スワイプでも進めます。2 ページ目をスワイプで飛ばすと位置情報の許可は一度も求められず、その後に求める場所がアプリ内にありません（`SplashView` は位置と通知の両方が許可済みのときだけ要求し、地図の `refreshLocation()` は未許可なら何もしません）。通知だけ拒否した場合も同じ分岐に入ります。
  - `NSLocationWhenInUseUsageDescription` / `NSLocationAlwaysAndWhenInUseUsageDescription` は**英語のみ**（`InfoPlist.xcstrings` なし）。日本語の端末でも、ダイアログの題は日本語、用途文は英語で出ます（`03-onboarding-location-dialog-ja.png`。アプリ名も小文字の「geomemo」）。**依頼を受けたとき、到着が依頼者に通知される**用途も書かれていません。
- 影響: 「常に許可」の取得率が下がり、アプリの中心機能（バックグラウンドの到着通知）が黙って働かなくなります。App Review 5.1.1 は、用途の説明が明確で完全であることを求めており、用途文に無い使い方（到着の第三者への通知）は指摘されやすい点です。
- 提案:
  1. 位置情報ページを「① 使用中の許可（地図に現在地を出す）」→「② 常に許可（アプリを閉じていても、登録した場所に着いたら知らせる。位置の履歴は保存しない・送信しない）」の 2 段にする。②は①の結果を待ってから表示し、「常に許可にする」と「あとで」の 2 つのボタンを置く。
  2. `requestAlwaysAuthorization()` の自動呼び出し（デリゲート内と Splash）をやめ、②のボタンと、最初のメモを保存した直後の案内からだけ呼ぶ。
  3. 用途文を日本語化し、依頼機能の用途を加える（例:「登録した場所への到着・出発を、アプリを閉じていても通知するために位置情報を使います。依頼を受け取った場合は、その場所に着いたことを依頼した人に知らせます。」）。
  - 1・3 の文言と用途文は UI のみの変更。2 は許可の要求タイミング（許可ロジック）を変えるため、クイックウィンには入れていません。

#### H-2 許可が足りない・監視できないとき、アプリ内で何も知らせない

- 画面: 地図、リスト、設定
- スクリーンショット: `60-settings-ja.png`（上部のみ。許可の行は写っていません）
- 確認: コード（`authorizationStatus` を読む画面は `SettingsView` と `SplashView` だけ。`LocationManager.startMonitoring` は 20 件超過をログに出すだけ）
- 問題:
  - 位置情報が「拒否」「使用中のみ」、通知が「拒否」でも、地図にもリストにも表示がありません。設定画面の「PERMISSIONS」に「使用中のみ」と出るだけで、それが何を意味するか（閉じていると通知されない）は書かれていません。
  - iOS のジオフェンスは 1 アプリ 20 件までです。超えた分は監視されませんが、ユーザーには分かりません（ルートは経由地ごとに 1 件使います）。
  - 設定の「通知」スイッチ（アプリ内）と、システムの通知許可の関係が分かりません。
- 影響: 「通知が来ない」というレビューや問い合わせの最大の原因になります。原因がユーザーから見えません。
- 提案:
  - 地図の上部に、状態に応じた 1 行のバナーを出す（「位置情報が『使用中のみ』です。アプリを閉じていると通知されません」＋「設定を開く」）。通知オフも同様。閉じたら 1 週間は出さない。
  - 設定の「位置情報」行の下に、状態ごとの説明をフッターで出す。
  - 監視できていないメモは、リスト行と詳細に「監視上限のため通知されません」の印を付け、上限に近づいたら編集画面で知らせる。

#### H-3 依頼を受け取る側の導線が途切れている

- 画面: リスト（受信した依頼）、受信した依頼の詳細
- スクリーンショット: `21-list-all-ja.png`、`50-received-detail-ja.png`
- 確認: 画面（リストの節、詳細に説明と完了ボタンが無く、操作は「この依頼を削除」だけであること）＋コード（メモ 0 件のときの分岐は画面では未確認。`ListTabView.swift` の `if memos.isEmpty { 空状態 } else { tabBar; pageContent }`、`receivedMemoRow`、`ReceivedSharedMemoDetailView.swift`）
- 問題:
  1. **自分のメモが 0 件だと、リストは「メモがありません」だけになり、受信した依頼の節が出ません。** 受け取るだけの人（例: 親・子ども）は、地図上の小さなピン以外に依頼を見つける手段がありません。
  2. 受信した依頼は「ALL」タブにしか出ません。
  3. **「完了」ボタンはリスト行にだけあり**（到着後のみ表示）、詳細画面にはありません。1. と合わせると、メモ 0 件の受信者は依頼を完了にできません。
  4. 詳細画面に「この場所に着くと、依頼した人に通知されます」「依頼者に伝わるのは到着と完了だけで、現在地は共有されません」の説明がありません。
  5. 共有リンクを開いて受諾した後、アプリは静かに同期するだけで、受け取った依頼を開きません。成功の表示もありません（失敗時はトースト）。
  6. 受信者への到着通知の本文が「（依頼者名）への到着を通知しました」で、「（依頼者名）という場所に着いた」とも読めます。
- 影響: 受信者は招待された側で、アプリに慣れていません。ここで迷うと依頼機能全体が成り立ちません。位置に関わる情報が他人に伝わることの説明は、信頼と審査（5.1.1 / 5.1.2）の両方で必要です。
- 提案:
  - リストの空状態の判定を「自分のメモも受信した依頼も無い」に変え、受信した依頼は常に先頭に出す。
  - 詳細画面の下部に、状態に応じた主ボタン（到着済みなら「完了にする」）と、依頼者に何が伝わるかの説明を置く。
  - 受諾後に受信した依頼の詳細を開き、「◯◯さんからの依頼を受け取りました」と出す。
  - 通知文を「◯◯さんに到着を知らせました」に直す。

#### H-4 送信画面で「誰に何が見えるか」が分からない

- 画面: 依頼する（`ShareMemoSheet`）、見守り、フレンド管理
- スクリーンショット: `40-share-sheet-ja.png`
- 確認: 画面（依頼する画面）＋コード（見守り・フレンド管理・確認ダイアログは画面では未確認。`ShareMemoSheet.swift`、`docs/sharing.md` の制限事項）
- 問題:
  - 相手に渡る内容（タイトル・本文・場所・範囲・期限）と、渡らないもの（写真、他のメモ、自分の現在地）が書かれていません。
  - 依頼者に戻ってくる情報（到着と完了の通知だけ。相手の現在地や移動は見えない）が書かれていません。画面名が「見守り」、状態が「監視中」なので、常時の位置追跡と誤解されやすい表現です。
  - 「リンクで送る」の説明は「共有シートで選んだ相手だけが受け取れます」ですが、**宛先の分からないアプリ（LINE 等）で送ると相手が開けない**という制限（`docs/sharing.md`）が画面にありません。日本では LINE で送ろうとする人が多いはずです。
  - フレンドを選んだ場合も「送る」を押すと共有シートが開きます。フレンドに直接届くと思った人は戸惑います（URL を自分で送る必要があることの説明がない）。
  - 「未確認」バッジは、選ぶ前には意味が分かりません（送る直前のダイアログとフレンド管理の脚注で初めて説明）。解消方法（相手から依頼を受け取る）は自分では操作できません。
  - 「現地到着で自動完了」の説明が「ONにすると発火と同時に完了通知を送ります」で、「発火」は内部用語です。
  - 送信に失敗したときの文言が「送信に失敗しました。もう一度お試しください。」だけで、iCloud 未サインイン・通信不可・フレンドの参加者を引けなかった、の区別がありません。
- 影響: 非公開招待に切り替えた安全性がユーザーに伝わらず、逆に「届かない」「見守り＝追跡」という誤解を生みます。
- 提案:
  - 送る相手の下に、3 行の説明カードを置く（「相手に見える: タイトル・メモ・場所・期限」「あなたに届く: 到着と完了の通知だけ。相手の現在地は見えません」「開けるのは選んだ相手だけ。リンクを転送しても他の人は開けません」）。
  - 「リンクで送る」の説明を「メッセージかメールで送ってください。LINE など宛先の分からないアプリでは相手が開けないことがあります」にする。
  - フレンドを選んだときの主ボタンの下に「次の画面で、◯◯さんにリンクを送ってください」と出す。
  - 「未確認」バッジをタップすると説明が出るようにし、文言を「本人確認前」など意味の分かる語にする。
  - 「発火」→「到着」、「監視中」→「到着待ち」（受信側の表記と揃える）。

#### H-5 地図のピンが小さく、VoiceOver で操作できない

- 画面: 地図
- スクリーンショット: `20-map-seeded-ja.png`（上部バーと右下のボタン。地図のタイルとピンは読み込み前で写っていません）
- 確認: コード（`MapPinViews.swift` `SinglePinView` は 12pt の円、`MapTabView.swift` は `Annotation("")` + `.onTapGesture`）
- 問題:
  - 単独ピンは 12×12pt、クラスタは 32pt、上部バーのボタンは 32×32pt。HIG の最小 44×44pt を下回ります。
  - 自分のメモのピンとクラスタは `onTapGesture` だけで、アクセシビリティのラベル・ボタン特性がありません（受信した依頼のピンには付いています）。VoiceOver ではピンを選べないか、名前のない要素になります。
  - 上部バーの「見守り」（目のアイコン）・検索・設定、地図右下の現在地・リストの各ボタンにラベルがありません（アセット名が読まれます）。メモ詳細の「依頼する」アイコンも同様です。
  - 完了済みのピンは `primaryText` の 30% で、モノクロ地図の上ではほぼ見えません。色だけで区別する 6 色ピンは色覚特性によって区別できません。
- 影響: 視覚・運動に制約のあるユーザーは地図を使えません。小さなピンは誰にとっても押しにくく、押し損ねると地図タップ（M-2 の位置の仮選択）として扱われます。
- 提案: ピンの見た目は保ったままタップ領域を 44pt に広げ、ラベル（タイトル、場所名、完了済みか）とボタン特性を付ける。アイコンだけのボタンすべてに `accessibilityLabel` を付け、タップ領域を 44pt にする。

#### H-6 日本語と英語が混在している

- 画面: 全体
- スクリーンショット: `03-onboarding-location-dialog-ja.png`、`60-settings-ja.png`、`35-editor-top-ja.png`
- 確認: 画面（用途文、設定の地図スタイル名、範囲の表記）＋コード（`geomemo/Localizable.xcstrings` を集計。`project.pbxproj` の `knownRegions` は `en, Base` のみ）
- 問題:
  - 共有機能（依頼する・見守り・フレンド管理・受信した依頼・プロフィール設定・関連トースト）は日本語をキーにしており、**英語訳がありません（カタログ上 63 件以上）**。英語設定のユーザーには日本語がそのまま出ます。
  - 逆に、英語キーで日本語訳が無いものが 31 件あります（「Favorite Places」「Add Place」「Edit Place」「Manage」「DWELL TIME」「Product unavailable」「Retry」「FRIENDS」「iCLOUD」など）。日本語設定で英語が出ます。
  - 許可ダイアログの用途文は英語のみ（H-1）。ウィジェットの説明「Shows your most important memos」も日本語訳なし。
  - `ClusterListSheet` の `"Unknown Location"` は `String` の三項演算子に入っているため、訳があっても英語のまま出ます（`CalloutView` は `String(localized:)` で正しい）。
  - 設定の地図スタイルは、日本語表示で「MONO / カラー / DETAIL / TRANSIT / SATELLITE」と 1 つだけ訳されています（`60-settings-ja.png`）。
  - 距離は `"\(Int(meters))m"` / `"%.1fkm"` の固定書式、範囲は「50M / 1KM」（大文字の M はメートルの表記として不自然）。ヤード・マイルの地域に対応していません。
  - 設定の節見出しや各ラベルが英語では全部大文字（NOTIFICATIONS、ADD MEMO、ON ENTRY）で、日本語では通常の表記。ブランドの個性ですが、全部大文字は読みにくく、VoiceOver が 1 文字ずつ読むことがあります。
- 影響: 英語圏のユーザーは依頼機能を使えません。日本語ユーザーには未完成に見えます。
- 提案: 日本語キーの文言に英語訳を、英語キーの 31 件に日本語訳を入れる。`InfoPlist.xcstrings` を追加する。距離は `Measurement` + `MeasurementFormatter`（または `.formatted(.measurement(...))`）に置き換える。`knownRegions` に `ja` を加える。

## 4. 新機能・改善の提案

### P-1 許可の案内を作り直す（「常に許可」の事前説明と、足りないときの案内）

- 内容: H-1・H-2 の本体。オンボーディングを「使用中 → 常に（理由つき、あとでも可）→ 通知」の順にし、各ダイアログは説明を読んでボタンを押したときだけ出す。地図に許可の状態のバナー、監視上限（20 件）の表示を足す。
- 根拠: アプリの価値はバックグラウンドの通知に依存している。現状は説明なしで 2 つ目のダイアログが出て、拒否されても気づけない。
- 工数: 中（2〜3 日）。
- リスク: 許可を求めるタイミングが変わるため、既存ユーザー（使用中のみで止まっている人）への再案内の出し方を決める必要がある。審査の説明文と合わせて確認する。実機での確認が必要。

### P-2 受信者のための「依頼」画面と受諾後の案内

- 内容: 共有リンクを受諾したら、依頼の内容・依頼者・「着いたら通知されること」をまとめた受け取り画面を出す。リストとは別に、受信した依頼だけを見る入口（地図上部のバッジ）を作る。受信だけの人には、メモ作成の UI を前面に出さない簡易表示にする。
- 根拠: 受信者は自分で入れたのではなく招待されて使い始める。現状は受諾後に何も起きず、メモが無いと依頼がリストに出ない（H-3）。
- 工数: 中（3〜4 日）。
- リスク: 受諾の処理（`didAcceptSharedMemo`）の後に画面を出すだけなら共有ロジックは変わらないが、初回起動（オンボーディング未完了）で受諾した場合の順序を設計する必要がある。

### P-3 見守り画面の作り直し（詳細・履歴・その場の操作）

- 内容: 依頼ごとの詳細画面（地図、状態の履歴「送信 → 受け取り → 到着 → 完了」、編集・送り直し・取り消し）。未送信・到着済みはカードで上に出し、ボタンで直接操作できるようにする。完了済みは折りたたみ。入口のアイコンに件数。画面名は「依頼した用事」など、追跡を連想させない名前を検討する。
- 根拠: 操作が長押しに隠れており、未送信という分かりにくい状態を解消する手段が見えない（M-4）。「見守り」「監視中」は、常時の位置追跡と誤解される。
- 工数: 中（3 日）。
- リスク: 名前の変更は App Store の説明・スクリーンショットにも波及する。「受け取り済み」を出すには共有の参加者の状態が必要で、取得の頻度に注意する（既存の `fetchVerifiedRecipients` の結果を使う範囲に留める）。

### P-4 地図を全面にして、リストを下部シートにする（Liquid Glass の採用）

- 内容: 地図を画面の端まで出し、上部の操作と右下のボタンを Liquid Glass にする。リストは下部のシート（小・中・大の 3 段、背景の地図は操作可能）にし、ピンを選ぶとシートがそのメモの概要に切り替わる。iPad は `NavigationSplitView`。
- 根拠: iOS 26 以降の地図アプリの定石と一致し、地図とリストの行き来（右下で開き、左上で戻る）と自前の 2 ペインを解消できる（M-1・M-11・M-12）。
- 工数: 大（1〜2 週間）。
- リスク: 画面の骨組みを変えるため、UI テスト・ディープリンク（`geomemo://memo/…`）・Live Activity からの遷移の確認が必要。ブランドの白黒・太字の見た目とガラスの相性は、試作で確かめる。

### P-5 メモ編集の段階的な開示と、範囲の調整

- 内容: 基本（場所・範囲・タイトル・着いたとき／離れたとき）と詳細（ルート、滞在、遅延、条件、色、タグ）に分ける。範囲はスライダーで 50m〜2km を調整し、編集画面の地図の円がその場で変わる。小さすぎる範囲（100m 未満）は「建物の中では反応しにくい」と注意を出す。
- 根拠: 作成が 1 番多い操作なのに、最も長く難しい画面になっている（M-10）。ジオフェンスは範囲が小さいと反応しないことがあり、4 択では場所に合わせにくい。
- 工数: 中（3〜4 日）。
- リスク: 範囲の値は既存の `radius`（Double）をそのまま使うのでスキーマは変わらないが、任意の値になるため、表示（50M などの固定ラベル）とウィジェット・Watch の表記を合わせる必要がある。

### P-6 「届かない」を自分で確かめられる通知の診断

- 内容: 設定に「通知のチェック」を作り、位置情報（常に／正確な位置）、通知、集中モード、低電力モード、監視中の件数（20 件中 n 件）、最後に到着を検知した時刻を一覧し、問題のある項目に直し方を出す。テスト通知を送るボタンも置く。
- 根拠: 位置の通知は、端末の設定に左右されやすく、原因がユーザーから見えない（H-2）。問い合わせと低評価を減らせる。
- 工数: 小〜中（2 日）。
- リスク: 「最後に検知した時刻」を端末に保存する場合、保存する情報は時刻だけにする（場所は保存しない）。プライバシーポリシーの記述と合わせる。

## 5. 付録

### 5.1 良い点（変えないほうがよい点）

- 共有まわりの空状態（iCloud 未サインイン／プロフィール未設定／フレンドなし／依頼なし）は、状態ごとに理由と次の行動が書かれている。
- 共有まわりの VoiceOver ラベル（「母、未確認」、行の状態、送信中）と `accessibilityHidden` の使い分けは適切。
- 送信に失敗・不明のときに「未送信」として残す設計は、黙って消すより安全（見せ方は M-4 を参照）。
- 折りたたみ端末・ウインドウ幅の変化に `horizontalSizeClass` で追従し、地図の状態を保つ実装。
- 完了・取り消しなどの触覚フィードバックが一貫している。
